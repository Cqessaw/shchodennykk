# Як редагувати щоденник

Коротко: майже все міняється прямо в застосунку, без коду. Код потрібен лише
для розкладу, переліку предметів та вигляду.

---

## 1. Що міняється без коду

Ці речі редагуються в самому застосунку, і якщо ввімкнено спільний режим —
зміни бачить увесь клас:

| Що | Де |
|---|---|
| Домашні завдання | вкладка **Щоденник**, «+ Додати завдання» |
| Оцінки | там само, кружечок біля предмета (залишаються лише на твоєму пристрої) |
| Навчальні суботи | шапка суботи, список «за який день» |
| Межі семестрів | вкладка **Розклад**, блок «Межі семестрів» |
| Посилання на підручники і ГДЗ | вкладка **Підручники**, олівець на картці |

**Щоб інша людина могла це редагувати** — їй достатньо відкрити сайт, увімкнути
спільний режим і ввести той самий код класу. Жодного доступу до коду не треба.

---

## 2. Як дати комусь редагувати код

GitHub → репозиторій → **Settings** → **Collaborators** → **Add people** →
ввести нікнейм. Людина отримає запрошення і зможе змінювати файли.

Без запрошення вона теж може допомогти: натиснути **Fork**, змінити у себе і
надіслати **Pull request** — ти подивишся і приймеш або ні.

---

## 3. Де що лежить

Весь застосунок — це **один файл `index.html`**. Решта допоміжна:

| Файл | Навіщо |
|---|---|
| `index.html` | розмітка, стилі й уся логіка |
| `sw.js` | офлайн-режим і кеш |
| `manifest.webmanifest` | назва та іконки для встановлення на телефон |
| `icons/` | самі іконки |

Усередині `index.html` шукай через Ctrl+F:

| Що змінити | Що шукати |
|---|---|
| Розклад уроків | `SCHEDULE_1` (перший семестр), `SCHEDULE_2` (другий) |
| Перелік і порядок підручників | `BOOK_SUBJECTS` |
| Дати семестрів за замовчуванням | `DEFAULT_SEMESTERS` |
| Кольори тем | `data-theme="latte"` та `data-theme="mocha"` |
| Підключення до бази | `FIREBASE_CONFIG` |

### Як влаштований розклад

```js
var SCHEDULE_1 = {
  1: [                                  // 1 = понеділок, 5 = п'ятниця
    {n:1, s:"Українська література"},   // n — номер уроку, s — назва
    {n:2, s:"Математика", sub:"Алгебра"} // sub — уточнення під назвою
  ],
  ...
};
```

Уроку немає — просто не пиши його рядок. Здвоєний урок пиши однією назвою:
`{n:6, s:"Заруб. літ. / Трудове навчання"}`.

Розклад другого семестру поки `null` — тоді показується перший. Щоб задати свій,
заміни `null` на такий самий об'єкт, як `SCHEDULE_1`.

## 4. Три способи редагувати

### На GitHub у браузері — працює і з телефона
1. Відкрити файл у репозиторії.
2. Олівець угорі праворуч.
3. Змінити текст.
4. **Commit changes**.

Сайт перезбереться сам за хвилину.

### На комп'ютері через GitHub Desktop
1. Відкрити `index.html` будь-яким редактором (підійде навіть Блокнот,
   зручніше — VS Code).
2. Зберегти.
3. У GitHub Desktop з'явиться список змін: написати короткий опис →
   **Commit to main** → **Push origin**.

### Просто файлом
`index.html` самодостатній: скопіюй його на флешку чи надішли в месенджер —
він відкриється й працюватиме будь-де. Але дані там будуть свої, окремі.

---

## 5. Головне правило

**Змінив `index.html` або `sw.js` — підніми версію кешу в `sw.js`:**

```js
var CACHE = "shchodennyk-v15";   // → v16
```

Інакше телефони показуватимуть стару версію: вони тримають збережену копію
і оновлюють її лише коли бачить нову назву кешу.

---

## 6. Якщо щось зламалося

Найчастіша причина — пропущена кома, дужка або лапка. Сторінка тоді відкриється
порожньою або без частини вмісту.

Повернути як було: GitHub → файл → **History** → обрати попередню версію →
**Revert**. Нічого не втрачається, бо збережена кожна зміна.

Домашні завдання й оцінки від правок коду не страждають: вони лежать окремо —
в пам'яті браузера та в базі кімнати.
